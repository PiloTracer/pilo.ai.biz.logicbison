# Changelog

All notable changes to Business OS are documented here.

## [v0.7.0] - 2026-10-25

### Added
- **Managed `.cursorrules` block — Business OS can now deploy into a project that already runs another OS framework** — the thin-client deploy skipped any existing `.cursorrules`, so a consumer that already had Agent OS or UI Design OS received `.work.biz/` and **no Business OS wiring at all**: no source pointer, no skills table, nothing that mentions the framework. Verified empirically before the fix (fixture with a foreign `.cursorrules`: `[FAIL] AI_BIZ_SOURCE: line missing`, and `update` reported a merge candidate that no script could apply). New `templates/cursorrules.biz.snippet.template` + `scripts/biz-cursorrules-merge.sh` install and refresh one region delimited by `<!-- BIZ_DESIGN_OS_BEGIN -->` / `<!-- BIZ_DESIGN_OS_END -->` (the marker convention the sister frameworks already use), appending it at the end of a foreign file without touching a single existing byte. `biz-deploy-basic` default mode now merges instead of skipping (`--no-merge` restores the old behaviour), `update` refreshes only the region, an unmatched marker is refused with a non-zero exit and an untouched file, and `biz-cursorrules-verify.sh --fix` appends the block to a target an older deploy left unwired. `biz-deploy-files` (fat-client) gets the same behaviour with `.ai.biz/` paths and no pointer. New `COHABITATION.md` states the ownership model for a multi-framework file (who owns which markers, which directories, how to recover), and `skills/biz-deploy-basic/skill.md` is rewritten around the five target states (`none` · `absent` · `present` · `legacy` · `unterminated`)
- **Canonical source path (`pwd -P`)** — the same framework was reachable as `/mnt/work/Projects/pilo.ai.biz.logicbison` and as the legacy `.ai.biz` symlink, so the deploy baked whichever name the caller happened to use. Two shells produced two different pointers for one physical framework, and the stale-pointer repair could not recognise its own paths. `biz-deploy-basic.sh`, `biz-cursorrules-merge.sh`, `biz-cursorrules-verify.sh`, `biz-deploy-files.sh` and `templates/bootstrap.sh` now canonicalise with `pwd -P`, and stale-pointer detection is naming-agnostic (`looks_like_biz_pointer`: `.ai.biz` substring, `pilo.ai.biz.*` basename, or a sibling that is a valid Business OS root) instead of requiring an `.ai.biz` segment that the real path does not contain
- **`@biz-strategy design` — generation and selection before certification** — `greenfield` walked one idea through eight elements, so the operator's first guess became the strategy and certification only measured internal consistency against it. New design mode (I1b) plus playbook `concepts/strategy-design/prompt.md` (BIZ-11): six-lens situation audit on graded evidence, seven business-model archetypes with cash timing and capacity ceilings, a competitive-alternatives map that puts **do nothing** first, 5–8 generated plays, six weighted criteria with an evidence-grade cap (a 4–5 resting on C/D evidence scores 2), forced ranking with a 2-point sensitivity swing, numbered "what would have to be true" conditions, an 11-row pre-mortem with observable kill signals, a moat taxonomy that deletes assertions with no evidence artefact, and a breakeven/sensitivity worksheet run for the top two plays. An existing strategy enters the ranking as a candidate rather than being silently replaced; rejected plays keep **re-entry conditions**
- **Certify checks 14–17** — alternatives recorded (design record, an `## Alternatives considered` section, or a specific recorded waiver), pre-mortem/kill signals, moat/durability, and sensitivity/breakeven. A strategy with none of the three alternatives artefacts can no longer be certified: its selection was never a decision
- **Counterfactual audit in `@biz-review quarterly`** — the decision audit scored what was chosen and could never answer whether the option that lost was better. The quarterly now reads the design record, checks whether a rejected play's re-entry condition fired, scores the **selection process** (`predicted` / `right for the wrong reason` / `wrong`), re-enters a winning rejected play through its recorded condition, reviews the bet kill signals, and feeds a `strategy-selection` class into the calibration table
- **`@biz-career` — job search, resume, interview and offer craft** — the framework answered "what should I sell" and "what can I prove" but nothing covered the **employment** side of the operator's market. New skill with five modes: `search` (three role archetypes, a channel plan with a capacity check, a 20–40 company target list with a route per row, a weekly cadence with a kill signal), `resume` (frame selection, bullet discipline, and an **evidence-recovery ladder** for thin experience instead of invented numbers), `interview` (story bank anchored to resume bullets, two failure stories, gap answers), `negotiate` (offer table with unverified figures marked, floor set in advance, one consolidated counter) and `status`. No gate; artifacts live in existing directories (no new scaffold, no re-bootstrap), and a bullet that cannot be traced to evidence is reported as a **gap**, never written as a claim
- **BIZ-12 — IT services strategy playbook** (`concepts/it-services-strategy/`) — strategy design was domain-neutral, so IT offers were modelled as generic "services". This adds the IT-specific layer: five **buying motions** (capability gap · bounded outcome · accountability gap · risk reduction · operational continuity) each with its budget owner, comparison set and offer shape; seven IT offer archetypes (staff aug, fixed-scope delivery, productized build, diagnostic, fractional CTO, managed service with an SLA, AI-assisted delivery) with cash shape and capacity ceiling; pricing architecture (floor from internal effective rate, graded anchors, scope units, change-order rule, day-rate conversion); the proof an IT buyer actually accepts; and a differentiation test — a constraint a competitor will not accept, or it is a slogan. `@biz-strategy design` reads it as a lens during D2–D4
- **BIZ-13 — Career search playbook** (`concepts/career-search/`) — the decisions behind `@biz-career`: the funnel with a fixed weekly budget (conversations × interview conversion × offer conversion), channel selection **without invented conversion rates**, the human-attention model of resume screening, the evidence-recovery ladder, structured-interview scoring, and negotiation as a pre-commitment rather than a tactics lesson
- **Verified source of record** (`docs/sources/verified-sources.md`) — 16 sources fetched and graded across IT services strategy, job search, and resume/interview, each with URL, date, grade and how to mine it, plus a **"what the evidence does not support"** section (no ATS-rejection percentage, no referral-conversion figure, no measured callback effect for keyword matching, no causal positioning→growth claim) and 12 explicitly **unverified** sources recorded so a later session does not mistake them for vetted. `@biz-sources find` now checks it before re-searching; `@biz-career` and BIZ-12/13 cite it
- **`CONVENTIONS.md` § Strategy design** — eight binding rules (comparison-or-waiver, incumbent competes, weights before scores, grade per score, re-entry conditions, observable kill signals, the choice is a decision, design never moves a gate) plus the default rubric, so the design loop is enforceable rather than advisory
- **`scripts/framework-verify.sh` regressions** — a foreign-`.cursorrules` merge fixture (block added, foreign bytes byte-identical, idempotent re-run, merged target verifies PASS, unmatched marker refused, `--fix` heals an unwired target), the canonical-pointer check, and a thin-client dead-reference guard on the template. The strategy-design wiring is checked too (playbook sections, the eight rules, design-mode strings, checks 14–17, the counterfactual audit, director routing, the design-record scaffold row, BIZ-11 registration)

### Changed
- **Thin-client template paths** — `templates/cursorrules.template` referenced framework files that do not exist in a consumer repo: `skills/SKILL_DEPENDENCIES.md`, `templates/work/touch-scope.template`, `.ai.biz/templates/cursorrules.template`, and `{SKILLS_ROOT}`/`{CONCEPTS_ROOT}` pointing at local directories. Every framework reference now states its thin (`$AI_BIZ_SOURCE/…`) and fat (`.ai.biz/…`) form, `START_HERE.md` is described as living in the framework root, the file-layout diagram no longer implies local `skills/`/`standards/`/`templates/` in thin-client, and the registry self row is baked to the source root by the deploy (the template keeps `*this directory*` for the self-hosted source)
- **Source registry cells** — the framework's own `.cursorrules` pointed `.ai.ui` and `.ai.soc` at `../.ai.ui` and `../.ai.soc`, which do not exist on this host, so `biz-cursorrules-verify.sh` FAILed the framework against itself. All seven cells now name the real family directories (`../pilo.ai.<fw>.logicbison`), and the file documents the managed-block contract
- **Deploy reporting is now what actually happened** — a target that was unwired and gained the block reported "refreshed mechanically"; the run now distinguishes *appended this run* / *refreshed this run* / *left as is*, and the "fill every `REPLACE:` token" step only appears when a full template was written
- **Unwritable targets fail cleanly** — a read-only `.cursorrules` (permissions, read-only mount, sandbox) produced a bare bash redirect error halfway through the append; the merge helper now checks writability first, composes the separator and the block into one payload so a failure cannot leave a half-appended file, and the deploy reports `BLOCKED: could not write … nothing else was written` and exits non-zero. Proven on a `chmod 444` fixture, and on the real `mendarion` run whose first attempt was denied by the file sandbox
- **`biz-deploy-files.sh` rsync** — `rsync -a` preserved uid/gid, and `chgrp` fails on filesystems that reject it, aborting the deploy (and therefore `framework-verify.sh`) with rsync exit 23. Now `-rlptD`: contents, symlinks, permissions and times, no ownership coercion — a deploy should not import another machine's numeric ids
- **Operator-facing report accuracy** — a merged target no longer tells the operator to "fill every `REPLACE:` token" (there are none in a merged block), block state is reported on every run, the misspelling `cursorules` is fixed in the deploy output, and the mode line states the merge behaviour

### Fixed
- **`biz-cursorrules-verify.sh` could delete the file it was verifying** — the scratch-copy cleanup trap was armed with the target's own `.cursorrules` path when no managed block existed, so a standalone or legacy target lost its rules file after a successful verification. The trap now covers only the temporary region copy; regression coverage asserts the file still exists after `verify` and after `update` in every layout
- **Verifier false positives in merged layouts** — the "unbaked `bash scripts/`" and source-resolution checks scanned the whole shared file, so another framework's own conventions produced Business OS failures. In a merged layout those checks now read only the business region; the sister framework's rules are never rewritten and never judged
- **First live cohabitation deploy verified** — `mendarion` (UI Design OS + Agent OS + Social OS already in its `.cursorrules`) went from `state=absent`, no Business OS wiring, to a merged managed block: `git diff --stat` shows **111 insertions, 0 deletions** (one blank separator + the 110-line block), the file's original 421 lines byte-identical, `.work.biz/` scaffolded, verification `PASS`
- **Migrated hand merges can name a dead pointer variable** — `--fix` correctly renames `AGENT_OS_SOURCE=` → `AI_BIZ_SOURCE=`, but a hand-merged section written before the rename keeps prose telling the agent to read `$AGENT_OS_SOURCE/…`, which no longer exists (or, in a multi-framework repo, is another framework's pointer). Found on `future-strategy`: the assignment had been migrated while six prose references still named the old variable, so an agent following rule 2 would have read the wrong tree. `biz-cursorrules-verify.sh` now warns on that mismatch inside the source-resolution section only (never rewriting another framework's text automatically), and the legacy merge rule in the deploy skill says to fix the prose, not the pointer
- **`--no-merge`, `merge` and `--layout <value>` argument forms** — two-token flags were unparsed (`--layout thin` errored as an unknown argument), and `--no-merge` is now a recognized verb in both the deploy script and its usage text

## [v0.6.3] - 2026-10-09

### Added
- **Decision loop — the judgment record and its calibration (`decisions/DECISIONS.md`)** — the framework measured voice (`VOICE_PROFILE` → `VOICE_RETRO`) and assumptions (`@biz-review monthly`), but never judgment: nothing compared a past recommendation with what actually happened, so advice could only get more confident, never more accurate. Verified absent framework-wide (zero hits for decision record, outcome tracking, base rate, pre-mortem, sensitivity, scenario analysis, or reversibility; the one real base rate the framework owns sat unused at `biz-discovery` L45). New append-only ledger `.work.biz/decisions/DECISIONS.md` with template `templates/work/decisions/DECISIONS.md.template`, recording one row per consequential decision: decision, options, rationale, **falsifiable expected outcome (number + date)**, **confidence %**, **reversibility** (one-way / two-way), **kill/review trigger**, review-by date, then the scored `Outcome` and `Lesson`, plus a **Calibration** table (hit rate vs mean confidence per class; `insufficient scored rows` below three) and a **Repeating-misses** rule (three misses in a class amend the rule, rather than a resolve to be more careful). Writers: `@biz-strategy certify`/`amend`, `@biz-advisory advise`, `@biz-pricing set`/`revise`, `@biz-market-validate test`, `@biz-proposal write`. Auditor: a new **Decision audit** in `@biz-review quarterly`, an overdue-row flag in the weekly drift check, and a dead-assumption cross-check in the monthly re-validation. Binding rules in `CONVENTIONS.md` § Decision loop (consequence test, record rule, scoring rule, calibration rule, empty-ledger warning). `@biz-proposal` gains **loss reasons** (`price` · `scope` · `timing` · `trust/fit` · `no decision` · `went in-house`), because a count of losses cannot separate a pricing problem from a qualification problem
- **Reality check — arithmetic + outside view at strategy certification** — the 10 certification checks were all qualitative except the shape of the price spread, so a strategy could certify "$20k–$80k via LinkedIn 3–4 posts/week" against 6 available hours a week without anyone checking that it closes. `biz-strategy` greenfield gains **Element 8**, two mandatory parts in `one-pager.md` § Reality check: **(A) arithmetic** — capacity, revenue ceiling at the floor price, required deals → proposals → conversations → prospects per week against the primary channel's realistic capacity, and runway against first revenue, every figure tagged with the existing `measured`/`estimated`/`assumption`/`unknown` vocabulary; **(B) outside view** — name the reference class, state what normally happens to it (graded, or `directional`), and reconcile the plan's timeline against it. New certify checks **11 Reality arithmetic**, **12 Outside view**, **13 Decision record**. `@biz-pricing` gains a pre-quote reality check (delivered margin surviving a two-week overrun, capacity, runway fit); `@biz-advisory` gains an outside-view step (4b) and a "does the math close" requirement on the primary direction
- **Evidence grades A–D + freshness** — evidence discipline was binary (an inline citation *or* a directional marker), so a vendor's marketing percentage and a first-party call note scored identically. `CONVENTIONS.md` § Evidence discipline gains a four-tier ladder (**A** first-party/primary · **B** named third-party research with a stated method · **C** vendor, consultancy, media claim, or single anecdote · **D** model memory or undated, never decisive alone), a rule that the grade is written next to the claim *in addition to* the citation, a note that the same author grades differently per claim and that syndicated copies are not corroboration, and a **Freshness** rule (18 months; 12 in fast-moving domains). Consumed by `@biz-advisory` step 4, the strategy `assumption-ledger.md` grade column, `@biz-pricing` anchors, `@biz-market-validate` new `Signal grade` field, and `@biz-sources` catalog entries

### Changed
- **Load-bearing assumptions replace the 30%-unknown metric** — certification check 3 counted unknowns, so a plan passed at 29% even when the single unknown was *whether anyone would pay*, while a well-tested plan with many trivial unknowns failed. Check 3 is now: no **load-bearing** assumption (anchoring buyer, problem, offer, primary channel, or price) may be Unknown or rest on grade-C/D evidence, with peripheral unknowns capped at 30%. The ledger gains `Load-bearing`, `If wrong` (the sensitivity pass), and `Grade` columns, reusing the load-bearing/peripheral vocabulary `@biz-review` already applies to dead assumptions. Probe now targets the largest blast radius first and carries a `Reality` question row
- **`@biz-director` never dead-ends and orchestrates the judgment layer** — new intent rows (record a decision · score past decisions · sanity-check a plan · outside view / timeline realism · evidence strength), a four-way **judgment-route disambiguation** for the requests that all sound like "is this right?", and a **no-match default**: ask one splitting question instead of presenting a menu of skill names; default to `@biz-advisory` when the request survives the probe (it hands off to the executing skill once a direction exists, which *is* the orchestration); default to `@biz-session status` + `@biz-review status` when the request is orientation in disguise; reach gap detection only after that. The director loads the decision ledger in I0, and its completion contract now requires a consequential recommendation to have landed as a row
- **Manifest sync (rule #22) and routing surfaces** — `decisions` added to the `bootstrap.sh` dir loop, `biz-deploy-basic.sh` `WORK_DIRS`, the `WORK_FILES` set (`decisions/DECISIONS.md`), `templates/README.md`, `templates/work/README.md.template`, `skills/biz-bootstrap/skill.md` § I1/I2 (with an `empty ledger` warning), and `skills/biz-deploy-basic/skill.md`. `standards/20260621-DIRECTORY_MAP.md` canonizes the directory and adds a **Decision rule**; `PROCESS_ROUTER.md`, `START_HERE.md` (decision tree, strategy and generative tables, resume table, reading order, anti-patterns), `skills/README.md` (skill rows + a `decisions` vocabulary entry), and `.cursorrules` + `templates/cursorrules.template` (a `{DECISIONS}` placeholder, `Before Claiming Completion` items 3–5, refreshed skill rows) are wired to match
- **`scripts/framework-verify.sh` — "Decision loop wiring" check block** — fails when the ledger template or any of its seven required columns disappears, when CONVENTIONS loses the Decision loop, Evidence grades, or Freshness rules, when DIRECTORY_MAP stops canonizing the directory, when any of the five writing skills stops appending rows, when `biz-strategy` loses load-bearing grading or the three new certify checks, when `biz-review` loses the Decision audit or its calibration step, when `biz-sources` loses grading, or when `biz-director` loses the no-match default or its ledger routing. The failure mode is silent by nature — an empty ledger looks exactly like a project with no decisions — so it gets the same treatment as `WORK_FILES` drift

## [v0.6.2] - 2026-08-21

### Added
- **`@biz-advisory` — situational business counsel skill** — the framework had strong workflows (strategy, pricing, sales, content) and generative skills (ideas, products) but nothing owned the messy "here is my situation — what should I do?" question; advice quality depended entirely on the model's native judgment. `biz-advisory` encodes the advisor craft as a protocol: I0 context contract (operator profile, strategy docs, pipeline evidence, capability fingerprint), a **mandatory reframe pass** (individuals → delivery unit, skill → productized outcome, history → first channel, competitor → complementor channel, tool fluency → control layer), ≥5 ranked options each with "don't sell X — sell Y" positioning and researched market precedent, mandatory **anti-advice** (what NOT to do — premature LLC/logo/website before customers), parallel-track sequencing with a 30-day frame, a decisive "what I would actually do", assumption ledger, quality checklist, completion gate. Calibrated against a real advisory case (laid-off architect + QA + developer team → product-rescue squad). Verbs: `advise` (default, free-text situation), `patterns`, `status`. Ungated; improves with strategy-ready
- **BIZ-10 Advisory Patterns** (`concepts/advisory-patterns/`) — the reusable judgment-pattern library `biz-advisory` draws on: 10 generalized patterns (team-as-product, productized entry offer, trigger-based demand, anchor channel, complementor channel, dual-track hedging, customers-before-company, modular configurations, control-layer positioning, outcome-over-people), each with when-it-applies, the move, and the failure mode

Verbs: `find`, `list`, `add`, `status`. Ungated; feeds the evidence passes of `biz-advisory`, `biz-ideas`, `biz-market-validate`, `biz-pricing`

### Added

Loose files, category READMEs, research notes, `_revert_*` backups, and the legacy `ideas/VOICE_STANDARD.md` fallback never move. Bootstrap scaffolds both directories (`templates/bootstrap.sh` dir loop + `biz-deploy-basic.sh` `WORK_DIRS`); routing wired through `skills/README.md` (skill row + `archive` verb, disambiguated from the `biz-deploy-repo` deploy mode), `biz-director` intents + gate-exempt table, `PROCESS_ROUTER.md`, `START_HERE.md`, `.cursorrules` + `templates/cursorrules.template`, root `README.md` (24 skills), and `SKILL_DEPENDENCIES.md` (ungated content-lifecycle utility)

### Changed
- **`biz-session` brought to full parity with Agent OS `session-control`** — the skill now supports the same parameter surface and semantics: `close commit [scoped] [push]` modifiers, **standalone `commit` / `commit push`** (scoped git checkpoint with NO HANDOFF/NEXT writes; the session stays open), a new **`add`** verb (stage the `.work.biz/` scope, show the draft message, no commit), `start - <goal>` goal capture, an unblock check, task-ref auto-detection (HANDOFF goal → `.work.biz/active-ref` → `.github/task-registry.json` → branch → last commit) with the ref written to `.work.biz/active-ref` for the `prepare-commit-msg` hook, a mandatory secrets scan that halts close/commit, always-shown commit messages (draft/used), and completion-checklist reports for start/close/commit. **Behavior change:** `commit` and `push` as bare invocations no longer imply `close` — `@biz-session commit` checkpoints mid-session and keeps the session open; close-time git requires `close commit` / `close commit push`. The `.work.biz/`-only write/stage/commit scope (path-scoped `git add -A -- .work.biz` + `git commit -- .work.biz`) is unchanged, and the CONTENT_STATUS pipeline brief on start is kept
- **Session routing surfaces** — `skills/README.md` (skill row + `commit`/`push` vocabulary + new `add` verb), `.cursorrules` + `templates/cursorrules.template` biz-session rows, `START_HERE.md` §6 (close variants + mid-session checkpoints), `.quick/session-lifecycle.md` (full command set), `SKILL_DEPENDENCIES.md` system-skills paragraph, `biz-director` session-management intents ("commit my progress", "checkpoint without closing"), and `PROCESS_ROUTER.md` (standalone commit row) all describe the new surface
- **`biz-session` commit scope is repo-role aware** — in the Business OS source repo (framework at git root, detected via `skills/biz-session/skill.md` at the root) `commit`/`push` stage and commit **all** modified/added/new files repo-wide (`git add -A`); in a target project the scope stays `.work.biz/` only. File writes remain `.work.biz/`-only in both roles. Owner directive: source-repo session commits must not leave framework changes behind
